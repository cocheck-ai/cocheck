# copilot-cli 1.0.103 live run

A real `copilot` 1.0.103 session with CoCheck's hooks installed (scratch HOME and data home): the main agent started tracking, launched three helpers with the `task` tool (a general-purpose agent building a workbook, the custom `memo-writer` agent writing a memo, a general-purpose agent building a deck), waited on them with `read_agent` calls, then ran one failing `ls`.

- raw-hook-stdin.jsonl: the real hook stdin of this run, 58 records, one `{event_arg, stdin}` per hook as the CLI fed it to the hook command, in firing order. Not rebuilt: `preToolUse` stdin is one call (`toolName`, `toolArgs`; `apply_patch` args are the patch text itself, `bash` args `{command, description}`), and a helper's calls carry `agentId`/`agentType`. Replayed by `test/copilot-write-credit.test.ts`. How it was made: the probe's capture file had 62 lines because concurrent hook writes interleaved (three `subagentStart` records were split across lines, wrapped in each other); each record was recovered by decoding the JSON objects and classifying it by its fields, not by any line prefix. Left out: the skill load and the `cocheck track start` command (first four records). Trimmed: tool results to 200 characters, non-`task` arguments to 300 characters (an `apply_patch` keeps its header line). The `agentDescription` field is dropped, the scratch root became `<scratch>`, and no `/Users/` or `/private/` path remains. The only prompts kept are the three `task` prompts. No file contents: the test writes stand-in files right after each writing call's Pre.
- hook-calls.jsonl (reconstructed, not the real stdin): 61 hook records in the shape of the 1.0.98 probe files (`event_arg` plus `stdin`), in the order the CLI fired them. Replayed by `test/copilot-read-agent-wait.test.ts`.

What the main agent's three `read_agent` calls look like: tool name `read_agent`, arguments `{"agent_id": "<helper>", "wait": true, "timeout": 180}`, all three open from before the helpers' first write until each helper finishes. They are waits: they write nothing.

How the file was made. The hook journal of the run had its bodies deleted, so the records are rebuilt from the CLI's own event log (`events.jsonl`, the `hook.start` entries, which hold each hook's input), not from the journal:
- A `preToolUse` input in that log is a batch (`toolCalls: [{id, name, args}, ...]`); each call became one `preToolUse` record with `toolName` and `toolArgs`, timestamped with the log line's time. The CLI's hook stdin for a Pre was not captured; the single-call form is the one the 1.0.98 files show.
- The log's hook inputs for a helper's tool and stop events lack `agentId`, `agentType` and `parentAgentId`; the log line around them carries `agentId`, and the helper's own first prompt carries the type. Those three fields were added to every helper event, as the 1.0.98 files send them.
- Left out: the skill load and the `cocheck track start` command (the test starts tracking directly), permission, transform and session events.
- Trimmed: every tool result keeps its result type and its first 200 characters; the arguments of a call other than `task` keep strings to 300 characters (a `task` call keeps its full prompt, which the helper link needs). The helpers' `agentDescription` field is dropped. No file contents are kept: the test writes stand-in files at the five Posts that wrote.
- Paths: `/private/tmp/.../t151-live/ws` became `<scratch>/ws` and the rest of that scratch root became `<scratch>`; no `/Users/` or `/private/` path remains. The prompts kept are the task's own (the main prompt and the three helper prompts).
- Not kept: the call ids the CLI logs (`call_...`). Replay uses the adapter's own synthetic ids.
